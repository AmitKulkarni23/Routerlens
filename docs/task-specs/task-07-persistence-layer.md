# Task 07 — Persistence Layer (Store Crate)

## Summary

Implement the `store` crate: an `sqlx`-backed repository over the schema
from Task 02, providing the write path the `probe`, `calibrate`, and
`detect_incidents` binaries all use. Handles run lifecycle
(`completed`/`partial`/`failed`), append-only call rows, item status
upserts, and incident insert/resolve. Uses `sqlx` offline mode so
`cargo build` does not require a live database connection in CI.

## Read First

- `docs/system-specs/architecture.md` §7 (Data model) — exact table/column
  shapes this crate's queries must target; §4 (Pipeline) — "a partially
  completed run is still a valid run; `runs.status` records
  `completed`/`partial`/`failed`".
- `docs/system-specs/architecture.md` §8 (Incident detection) — the query
  shape `detect_incidents` (Task 10) will need from this crate: per-provider
  daily pass rate history for a rolling window.
- `supabase/migrations/*.sql` (Task 02 output) — the concrete column names
  and types to write `sqlx` queries against; run `cargo sqlx prepare`
  against a live copy of this schema to generate the committed offline
  query cache.

## Requirements

### Run lifecycle

- The crate MUST expose `pub struct Store { pool: sqlx::PgPool }` with
  `pub async fn connect(database_url: &str) -> Result<Store, sqlx::Error>`.
- MUST expose `pub async fn start_run(&self, bank_version: u32, git_sha: Option<String>) -> Result<Uuid, sqlx::Error>`
  that inserts a `runs` row with `started_at = now()`, `status` not yet
  finalized (implementer's choice: a transient status value or a nullable
  `status` that is only set on finish — MUST NOT default to `completed`
  before the run actually finishes).
- MUST expose `pub async fn finish_run(&self, run_id: Uuid, status: RunStatus) -> Result<(), sqlx::Error>`
  where `RunStatus` is an enum `{ Completed, Partial, Failed }` mapped to
  the `runs.status` string values, setting `finished_at = now()`.

### Call and item-status writes

- MUST expose `pub async fn insert_call(&self, call: NewCall) -> Result<(), sqlx::Error>`
  where `NewCall` carries every field of a `calls` row except `id` and
  `created_at` (which the database generates). This method MUST be called
  once per work item outcome regardless of `call_ok` — pass and fail rows
  alike.
- MUST expose `pub async fn get_item_status_map(&self) -> Result<HashMap<String, ItemStatusValue>, sqlx::Error>`
  loading all `item_status` rows keyed by `item_id`, where
  `ItemStatusValue` is an enum mirroring the four DB status values.
- MUST expose `pub async fn upsert_item_status(&self, item_id: &str, status: ItemStatusValue, reason: &str) -> Result<(), sqlx::Error>`
  using `INSERT ... ON CONFLICT (item_id) DO UPDATE`.

### Incident writes and rolling stats read

- MUST expose `pub async fn get_daily_pass_rates(&self, provider: &str, days: u32) -> Result<Vec<(chrono::NaiveDate, f64)>, sqlx::Error>`
  reading from the `daily_provider_stats` view (Task 02), ordered by date
  ascending, limited to the trailing `days` days.
- MUST expose `pub async fn insert_incident(&self, provider: &str, metric: &str, baseline: f64, observed: f64, delta: f64) -> Result<Uuid, sqlx::Error>`.
- MUST expose `pub async fn get_open_incident(&self, provider: &str) -> Result<Option<Uuid>, sqlx::Error>`
  (an incident row for the provider with `resolved_at IS NULL`).
- MUST expose `pub async fn resolve_incident(&self, incident_id: Uuid) -> Result<(), sqlx::Error>`
  setting `resolved_at = now()`.
