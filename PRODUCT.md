# Product

## Register

product

## Users

Engineers and software professionals evaluating or monitoring LLM hosting providers on OpenRouter. Technically fluent — they understand quantization, latency percentiles, and cost trade-offs. They arrive with a question ("which provider is actually serving quality outputs for this model?") and want the answer fast, with evidence. Context: working session, likely split-screen with code or an OpenRouter dashboard.

## Product Purpose

Routerlens measures per-provider output quality for the same model on OpenRouter. OpenRouter routes on price/speed/uptime, not output quality — Routerlens fills that gap with mechanical grading, timestamped history, and incident detection. Success: a user checks Routerlens, sees which providers are actually returning correct answers today, and makes an informed routing decision in under 30 seconds.

## Brand Personality

Precise, transparent, calm. A measurement instrument, not a marketing tool. Shows data without editorializing — no ranking language, no winners, no hype. Trustworthy because it's boring in the right ways.

## Anti-references

- Marketing SaaS dashboards: no gradients, hero metrics, gamification, upsell patterns, or "your team saved 47% this week" energy.
- Generic Bootstrap/admin panels: no cookie-cutter admin template feel, no gray-on-gray monotony.
- Overdesigned data viz tools: no 3D charts, excessive animation, or style over substance.

## Design Principles

1. **Data first, chrome second.** Every pixel of UI should serve the data or get out of the way. If removing an element doesn't hurt comprehension, remove it.
2. **Earned trust through transparency.** Show methodology, show timestamps, show error rates alongside pass rates. Don't hide the messy parts.
3. **Measurement, not judgment.** Present facts. No ranking language, no "best provider," no color-coding that implies winners and losers.
4. **Respect expertise.** Users are technical — don't over-explain, don't simplify away useful detail. Dense is fine when it's clear.
5. **Calm confidence.** The interface should feel like a well-calibrated instrument: reliable, precise, unhurried.

## Accessibility & Inclusion

WCAG 2.1 AA minimum. Charts must not rely solely on color to distinguish providers — use pattern, label, or shape differentiation. Reduced motion alternatives for any transitions. Ensure data tables are screen-reader accessible.
