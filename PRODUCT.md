# Product

## Register

brand

## Users

**Primary:** Engineering leaders and recruiters arriving via a shared portfolio link. Context: skimming in under 10 seconds, forming a judgment about the builder's technical taste and execution quality. They're not here to compare LLMs — they're here to evaluate the person who built this.

**Secondary:** Technically curious visitors who actually want to use the tool — type a prompt, watch 2–6 models respond in parallel, compare outputs.

Job to be done: The recruiter needs a fast, clear signal of engineering competence. The tool user needs the interface to stay out of the way while models stream.

Emotional goal: confident authority — this was built deliberately, not assembled from a template.

## Product Purpose

Chorus is a live demo and portfolio piece that surfaces as a real tool. One prompt fans out to N free-tier LLMs simultaneously via OpenRouter; responses stream side by side in real time. No ranking, no judging, no consensus — pure parallel inference displayed honestly.

Success looks like: a recruiter loads the page, types a prompt, and thinks "whoever built this knows what they're doing."

## Brand Personality

Precise. Deliberate. Understated.

Voice: minimal commentary, confident defaults, no hand-holding. The interface defers to the content (the streaming responses) — it doesn't compete with it.

## Anti-references

- **ChatGPT / Claude UI** — chat-clone aesthetic, light bubbles, familiar conversational chrome. Chorus is a comparison tool, not a chatbot.
- **Generic AI SaaS landing** — cream/sand background, gradient hero, metric cards, section eyebrows. The 2024–2026 AI startup template.
- **Colorful / consumer AI tools** — Perplexity, Poe: pastel palettes, rounded-corner friendliness, consumer-app energy. Chorus is a builder's tool, not a consumer product.
- **Academic research demo** — dense, utilitarian, Hugging Face Spaces energy. No visual investment.

## Design Principles

1. **Engineering as the voice.** The tool's architecture is what impresses — the design must get out of the way and let the parallel streaming speak. No decorative distraction.
2. **Dark by conviction, not convention.** Dark mode because this is a technical tool for technical people in focused contexts — not because dark looks cool. The choice must feel earned.
3. **Motion on content, not chrome.** Streaming tokens are the live moment; animate that. Transitions on structural UI elements should be quick and purposeful, never ornamental.
4. **Deliberate neutrality rendered visually.** The product never judges which model is better. The design must encode that philosophy — equal panel weight, no visual hierarchy between model outputs.
5. **Reference: Linear.** Dark surfaces with confident typography, smooth micro-interactions, premium density without clutter. Motion that feels engineered, not sprinkled on.

## Accessibility & Inclusion

No formal WCAG target (PoC). Make it readable. Dark background with high-contrast text — the aesthetic enforces good contrast naturally.
